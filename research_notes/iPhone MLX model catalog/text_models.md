# Compact text-only MLX language models for Beacon (as of 2026-09-29)

## Which missing models materially add a new capability or better quality/size tradeoff?

### Takeaway
Add `mlx-community/MiniCPM5-2B-mlx-4Bit` first and `mlx-community/Qwen3-4B-Instruct-2507-4bit` as the premium sub-3 GB tier. Treat `mlx-community/Phi-4-mini-instruct-4bit` as a replacement for Phi-3.5 Mini, not another parallel catalog entry; it is a meaningful generational improvement but occupies almost exactly the same size/capability niche.

#### Recommended catalog replacement

| Decision | Exact repository ID and direct URL | Rationale |
|---|---|---|
| Replace Phi-3.5 Mini with Phi-4 Mini after device validation | [`mlx-community/Phi-4-mini-instruct-4bit`](https://huggingface.co/mlx-community/Phi-4-mini-instruct-4bit) | Microsoft calls Phi-4 Mini a 3.8B dense, text-input, instruction-tuned model with 128K context, stronger post-training, function calling, and a larger multilingual vocabulary. In Microsoft's same-platform comparison it scores 63.5 overall versus 60.5 for Phi-3.5 Mini, including BBH 70.4 versus 63.1, MMLU-Pro 52.8 versus 47.4, GSM8K 88.6 versus 76.9, and MATH 64.0 versus 49.8, although Phi-3.5 remains ahead on Arena-Hard, GPQA, HellaSwag, PIQA, and several other tasks. Since Beacon already carries Phi-3.5 Mini at essentially the same 2.15 GB catalog size, keeping both would be duplicative; Phi-4 is best considered an upgrade rather than a new niche. — [Microsoft model card and benchmark table](https://huggingface.co/microsoft/Phi-4-mini-instruct); [MLX repository/API](https://huggingface.co/api/models/mlx-community/Phi-4-mini-instruct-4bit?blobs=true) |

- MiniCPM5 is unusually efficient in download terms: its current snapshot is 1.426 GB for 2.517B parameters, versus 2.279 GB for Qwen's 4.022B parameters and 2.180 GB for Phi-4 Mini's 3.836B parameters. Parameter count and encoded file bytes are different measurements and should never be used interchangeably. — [MiniCPM5 API](https://huggingface.co/api/models/mlx-community/MiniCPM5-2B-mlx-4Bit?blobs=true); [Qwen API](https://huggingface.co/api/models/mlx-community/Qwen3-4B-Instruct-2507-4bit?blobs=true); [Phi API](https://huggingface.co/api/models/mlx-community/Phi-4-mini-instruct-4bit?blobs=true)
- MiniCPM5's upstream card specifies a standard `LlamaForCausalLM`, 2,516,756,480 parameters, 42 layers, 131,072-token context, and explicit on-device/resource-constrained positioning. This is a differentiated quality-per-byte and coding/agent option, despite some overlap with Beacon's specialist Qwen2.5 Coder 3B. — [Upstream MiniCPM5 card](https://huggingface.co/openbmb/MiniCPM5-2B)
- Qwen3-4B-Instruct-2507 is explicitly a post-trained causal language model with 4.0B parameters (3.6B excluding embeddings), 36 layers, and non-thinking-only output. That makes it a conventional chat model rather than another visible reasoning-trace model. — [Upstream Qwen model card](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)
- Phi-4 Mini is explicitly intended for constrained and latency-sensitive environments and strong math/logic reasoning, but Microsoft also warns that its small size limits factual capacity and that non-English performance is uneven. — [Microsoft model card](https://huggingface.co/microsoft/Phi-4-mini-instruct)

### Inferences

- MiniCPM5 should be the default next addition: it supplies the strongest claimed 2026-era quality/size tradeoff, uses the most conventional architecture of the shortlist, and has enough download headroom for iPhone storage and memory constraints. This conclusion combines its 1.426 GB snapshot and `llama` configuration with the upstream on-device positioning and reported evaluations. — [MLX API](https://huggingface.co/api/models/mlx-community/MiniCPM5-2B-mlx-4Bit?blobs=true); [upstream card](https://huggingface.co/openbmb/MiniCPM5-2B)
- Qwen3 4B is the better premium addition for users willing to spend roughly 0.85 GB more download than MiniCPM5. It is not a new architecture or family for Beacon, but the vendor's measured jump over the original Qwen3 4B and the gap from Beacon's 1.7B checkpoint are large enough to create a distinct high-quality tier. — [Qwen model card](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507); [MLX API](https://huggingface.co/api/models/mlx-community/Qwen3-4B-Instruct-2507-4bit?blobs=true)
- Phi-4 Mini has a sound upgrade case but a weak additive case. Its strongest gains are math, BBH, MMLU-Pro, and multilingual math, while Phi-3.5 wins several conversational/knowledge tasks; an A/B device evaluation should precede removing Phi-3.5. — [Microsoft comparison](https://huggingface.co/microsoft/Phi-4-mini-instruct)
- A nominal 128K-256K context window is not a practical iPhone operating target. KV-cache and prompt-processing memory grow with context, so Beacon should retain conservative context/output limits even when the model card advertises much larger windows. Qwen itself advises reducing context to 32,768 when out of memory. — [Qwen model card](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)

### Gaps

- No independent benchmark suite was found that compares the September 2026 MiniCPM5 release against Beacon's exact 4-bit conversions on iPhone hardware. Its striking advantage is presently supported primarily by OpenBMB's own evaluation.
- No on-device measurements were performed for peak memory, time to first token, sustained tokens/second, thermal throttling, or long-chat stability. Repository size only establishes download practicality, not runtime memory safety.
- “Modern iPhone” spans materially different RAM capacities. MiniCPM5 should be the lower-risk candidate; Qwen3 4B and Phi-4 Mini should be validated on Beacon's minimum supported device before catalog publication.

## What are the exact metadata and pinned-runtime compatibility results?

### Takeaway
All three shortlisted repositories are public, ungated, have clear permissive licenses, remain below 3 GB for the complete current snapshot, include chat templates, and expose a `model_type` explicitly registered by `mlx-swift-lm` 3.31.3. This is strong static evidence for Beacon's generic `ModelConfiguration(id:)` path, but not a substitute for an iOS load/generation smoke test.

### Inferences

- **Static compatibility verdict: yes for all three.** Their exact `model_type` strings are explicit keys in the pinned registry, and all have the expected MLX quantization/config/tokenizer assets. No repository-specific registry constant or Beacon switch case should be necessary for text generation. — [Pinned registry/loader](https://github.com/ml-explore/mlx-swift-lm/blob/1c05248bb0899e2a7a4962b84d319cf12f4e12aa/Libraries/MLXLLM/LLMModelFactory.swift); [MiniCPM5 API](https://huggingface.co/api/models/mlx-community/MiniCPM5-2B-mlx-4Bit?blobs=true); [Qwen API](https://huggingface.co/api/models/mlx-community/Qwen3-4B-Instruct-2507-4bit?blobs=true); [Phi API](https://huggingface.co/api/models/mlx-community/Phi-4-mini-instruct-4bit?blobs=true)
- MiniCPM5 is the least architecturally risky because it deliberately emits a standard Llama configuration. Qwen is also low risk because Beacon already runs smaller `qwen3` models. Phi-4's reuse of `phi3` is registered, but its architecture changes and 200K vocabulary make an actual iOS test more important than the type name alone. — [MiniCPM5 card](https://huggingface.co/openbmb/MiniCPM5-2B); [Phi card](https://huggingface.co/microsoft/Phi-4-mini-instruct); [pinned registry](https://github.com/ml-explore/mlx-swift-lm/blob/1c05248bb0899e2a7a4962b84d319cf12f4e12aa/Libraries/MLXLLM/LLMModelFactory.swift)

### Gaps

- Registry membership proves that 3.31.3 recognizes the architecture; it does not prove every field combination, tensor name, tokenizer construct, EOS token, or generation behavior works in Beacon. No repository-specific iOS smoke test or upstream Swift integration test was found for these exact three IDs.
- Hugging Face does not expose a single authoritative “app download bytes” property. The current-snapshot sum is reproducible from the API and is the most conservative fresh-download figure, while an actual downloader may omit README and Git metadata or reuse cached tokenizer files.
- The MLX MiniCPM5 card says it was converted from an intermediate `adrgrondin` repository even though the repository metadata points to `openbmb/MiniCPM5-2B`. The weights/config metadata and upstream model identity are coherent, but the stale generated README attribution should be treated as a provenance-documentation blemish. — [MLX conversion card](https://huggingface.co/mlx-community/MiniCPM5-2B-mlx-4Bit); [API metadata](https://huggingface.co/api/models/mlx-community/MiniCPM5-2B-mlx-4Bit?blobs=true)

## Which candidates should be excluded?

### Takeaway
Exclude models that are base-only, multimodal rather than text-only, over the practical snapshot/memory envelope, license-risky, or redundant with stronger catalog entries. Ministral 3 3B is the most tempting near-miss: it is capable and runtime-supported, but the available official MLX conversion carries a vision encoder and is therefore not a clean text-only catalog addition.

### Inferences

- The strict shortlist should remain small: MiniCPM5 adds a new 2026 quality/size and agent/coding point; Qwen3 4B adds a premium general tier; Phi-4 replaces an incumbent. Every other reviewed model either duplicates an existing family/niche or violates text-only, licensing-priority, or memory goals.
- “Ungated” on an MLX conversion only means the conversion can be downloaded without access approval. It does not convert a custom upstream license into an open-source license or remove attribution/use obligations, as the ungated Llama conversion demonstrates. — [Llama API and embedded license](https://huggingface.co/api/models/mlx-community/Llama-3.2-3B-Instruct-4bit?blobs=true)
- Models near 3 GB deserve a stricter memory bar than models near 1.5 GB because weights are only part of runtime memory; tokenizer state, Metal allocations, activations, and KV cache add to the working set. This is why Ministral is a poor text-only catalog choice even before accounting for its bundled vision encoder. — [Ministral repository metadata](https://huggingface.co/api/models/mlx-community/Ministral-3-3B-Instruct-2512-4bit?blobs=true); [Ministral architecture card](https://huggingface.co/mistralai/Ministral-3-3B-Instruct-2512)

### Gaps
